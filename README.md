# Bash Scripting Projects

This repository contains two Bash scripting tasks, both organized under a single `financial/` project folder:

1. **ETL Pipeline** — A script that downloads a CSV file, transforms it, and is scheduled to run automatically using `cron`.
2. **Move CSV/JSON Files** (`move_files/`) — A utility script that finds and moves all `.csv` and `.json` files from one folder into a destination folder called `json_and_CSV`.

Both are written in pure Bash,  and are version-controlled using Git.

## Project 1: Financial ETL Pipeline

### Purpose
To build a Bash script that performs a simple ETL process on New Zealand's Annual Enterprise Survey data:

- **Extract** — Download a CSV file from a public URL and save it to a `raw` folder.
- **Transform** — Rename a column, Variable_code to variable_code, and save the result to a `Transformed` folder.
- **Load / Schedule** — Automate the entire process to run daily using `cron`.

### Data Source
[Stats NZ – Annual Enterprise Survey 2023 (Financial Year, Provisional)](https://www.stats.govt.nz/assets/Uploads/Annual-enterprise-survey/Annual-enterprise-survey-2023-financial-year-provisional/Download-data/annual-enterprise-survey-2023-financial-year-provisional.csv)

### How It Works

**1. Environment Variable Setup (`.env`)**
The download URL is stored as an environment variable rather than hardcoded directly into the script. A `.env` file holds:
```bash
export csv_url="https://www.stats.govt.nz/assets/Uploads/Annual-enterprise-survey/Annual-enterprise-survey-2023-financial-year-provisional/Download-data/annual-enterprise-survey-2023-financial-year-provisional.csv"
```
The main script `source`s this file at the very start, so the variable is loaded fresh every time the script runs — whether triggered manually or by `cron`.

**Why a `.env` file was used instead of `export`ing the variable directly in the terminal:**

The first version of this script relied on `csv_url` being set manually in the terminal with:
```bash
export csv_url="https://..."
```
This worked fine when running the script by hand, immediately after setting the variable, in the same terminal session. However, it broke in two important ways:

1. **It doesn't survive across sessions.** An `export`ed variable only exists in the memory of the specific terminal session it was set in. Closing that terminal, opening a new tab, or restarting the machine wipes it out completely — there is no file on disk backing it up.
2. **`cron` never sees it at all.** `cron` runs jobs in its own minimal, non-interactive environment, completely separate from any personal terminal session. It has no knowledge of variables you've `export`ed manually, no matter how recently. This was confirmed directly during testing — the script failed under `cron` with `curl: option : blank argument where content is expected`, because `$csv_url` was empty in cron's environment.

Putting the variable in a `.env` file and having the script `source` that file **from disk, every time it runs**, solves both problems: the value is defined once, persists permanently as a file, and is loaded fresh into the script's own environment on every execution — regardless of how it was ran. 
**2. Extract Step**
- Creates a `raw/` folder (if it doesn't already exist) using `mkdir -p`.
- Downloads the CSV using `curl -L` (the `-L` flag follows any redirects).
- Confirms the download succeeded by checking that the file exists **and** is not empty (`[ -s file ]`), then prints the file size using `ls -lh`.
**3. Transform Step**
- Renames the `Variable_code` column header to `variable_code` using `sed`.
- Uses `awk` to dynamically locate the `Year`, `Value`, `Units`, and `variable_code` columns by name (not fixed position), then extracts just those columns into a new file.
- Saves the result to `Transformed/2023_year_finance.csv`.
- Confirms the output file exists and is not empty, then previews the first few lines with `head`.

**Explanation of the cron syntax:**
```
0 0 * * *
│ │ │ │ │
│ │ │ │ └── day of week (any)
│ │ │ └──── month (any)
│ │ └────── day of month (any)
│ └──────── hour (0 = midnight)
└────────── minute (0)
```

- `>> cron.log` appends the script's normal output to a log file (rather than overwriting it each run).
  
- `2>&1` redirects error output (stderr) to the same place as normal output (stdout), so any failures are also captured in the log — not just successful runs.

**To view or edit the schedule:**
```bash
crontab -l     # list current cron jobs
crontab -e     # edit cron jobs
```

**Testing approach:** Before finalizing the midnight schedule, the job was temporarily scheduled a few minutes into the future to confirm it executed correctly end-to-end (verified via `cron.log`), then switched to the final `0 0 * * *` schedule.

### Issues Encountered & Fixes

| Issue | Cause | Fix |
|---|---|---|
| `curl: option : blank argument where content is expected` | `csv_url` was set with `export` in an interactive terminal, but `cron` doesn't inherit terminal-exported variables | Moved the URL into a `.env` file and `source`d it inside the script itself |
| `Permission denied` when run by cron | Script lacked execute permission | `chmod +x financial_script.sh` |
| `Operation not permitted` from `/bin/bash` | macOS Full Disk Access restrictions blocking cron/Terminal | Added Terminal (and `/usr/sbin/cron`) to **System Settings → Privacy & Security → Full Disk Access** |
| `sed: bad flag in substitute command` | Missing space between the `sed` command and the filename argument | Added the missing space |
| `awk: syntax error` | Missing space/quote between the `awk` program and the filename argument | Corrected quoting and spacing |
| `Transformed` folder nested inside `raw/` instead of at the project root | Script was run from inside `raw/`, or `mkdir` used a relative path incorrectly | Moved the folder to the correct location and fixed the script's working-directory assumptions |
| GitHub still showed the old folder structure after reorganizing locally (e.g. moving `move_csv_json.sh` into `move_files/`) | Moving files locally (via Finder/editor) does not automatically update Git — Git only reflects what has been staged, committed, and pushed | Ran `git add -A` (stages new files **and** deletions together, not just new files) then committed and pushed again |

## Project 2: Move CSV and JSON Files (`move_files/`)

### Purpose
Write a Bash script that moves **all `.csv` and `.json` files** from a source folder into a destination folder named `json_and_CSV`, correctly handling one or more files of each type, and correctly leaving other file types untouched.

### Sample Test Data
To demonstrate the script works with multiple files of each type, the following sample files were created in `files_to_move/`:

| File | Type | Description |
|---|---|---|
| `employees.json` | JSON | Array of employee records |
| `inventory.json` | JSON | Nested object with warehouse inventory data |
| `sales.csv` | CSV | Order/sales transaction data |
| `weather.csv` | CSV | Daily weather readings |
| `notes.txt` | TXT | Included to confirm the script correctly **ignores** non-matching file types |

### How It Works

```bash
#!/bin/bash

source_folder="files_to_move"
destination_folder="json_and_CSV"

mkdir -p "$destination_folder"

count=$(find "$source_folder" -type f \( -name "*.csv" -o -name "*.json" \) | wc -l | tr -d ' ')

find "$source_folder" -type f \( -name "*.csv" -o -name "*.json" \) -exec mv -v {} "$destination_folder"/ \;

moved_count=$(find "$destination_folder" -maxdepth 1 \( -name "*.csv" -o -name "*.json" \) | wc -l | tr -d ' ')
```

**Key techniques used:**
- **`find ... -type f \( -name "*.csv" -o -name "*.json" \)`** — Recursively searches for files ending in `.csv` OR `.json`. The parentheses group the two conditions together (escaped with backslashes so the shell doesn't interpret them), and `-o` means "or."
- **`-exec mv -v {} destination/ \;`** — Runs `mv` once for every file `find` matches. `{}` is replaced with each matched file's path; `\;` marks the end of the `-exec` command. The `-v` flag prints each move as it happens.
- **`wc -l`** — Counts the number of matching lines (i.e., files) returned by `find`.
- **`tr -d ' '`** — Strips leading whitespace that `wc -l` sometimes adds, ensuring the count is a clean number safe for numeric comparisons (`-gt`, `-eq`, etc.).
- **Verification step** — After moving, the script re-checks the destination folder directly (rather than assuming the move succeeded) and reports success or failure accordingly.

### Running the Script
```bash
cd financial/move_files
chmod +x move_csv_json.sh
./move_csv_json.sh
```

### Expected Result
- `employees.json`, `inventory.json`, `sales.csv`, and `weather.csv` move into `json_and_CSV/`.
- `notes.txt` remains untouched in `files_to_move/`.

## Git Version Control

Both projects are tracked using Git to satisfy the requirement that **"all work must be versioned using Git."**

### Key practices followed:
- `git init` to initialize the repository.
- Regular, logically-scoped commits made throughout development (not one single commit at the end).
- A `.gitignore` file to exclude irrelevant or system-generated files:
  ```
  .DS_Store
  **/.DS_Store
  .env
  ```
  (`.DS_Store` is a macOS-only Finder metadata file with no project relevance. `.env` is excluded as good practice for keeping configuration separate from code.)
  
### Common commands used:
```bash
git status                  # check what's changed
git add <file>               # stage changes
git commit -m "message"      # save a snapshot
git push                     # send commits to GitHub
git log --oneline            # view commit history
```
